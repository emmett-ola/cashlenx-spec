# 1.1.9 — Make log output configuration-owned and ship JSON on stdout

## Status

- Version: `1.1.9`
- Type: feature — server logging configuration and stdout encoding. No API,
  schema, persistence or routing change.
- State: delivered on `develop`; **not accepted** — acceptance is recorded by
  someone who did not implement it, and no tag exists.
- Date: 2026-11-22.
- Scope: `cashlenx-server` (`util/`, `.env.example`) and this record.

## Why

`CLX-105` can only be diagnosed from a server log line that carries a
`request_id`. The owner's decision is that log visibility comes from the
observation platform, and the platform side is handed to `linden`
(`ASIDE spec/records/handoffs/2026-11-22-observability-log-ingest-handoff.md`).

The client side had three gaps in the way of any collector:

1. Files rolled only by day and the name was hard-coded, so a directory layout
   or an hourly shard was a code change.
2. `LOG_FOLDER` was the only directory key, and a value that looked like a
   filename was repaired by string surgery.
3. stdout used the development text encoder while the file used production
   JSON, so a container-native collector had to parse prose.

## What changed

| File | Change |
| --- | --- |
| `util/log_rolling.go` | new rolling writer: template expansion, `daily`/`hourly`/`size` rotation, size sharding, retention pruning |
| `util/log_util.go` | writer built from settings; console encoder selectable; the old `dailyLogWriter` is deleted |
| `util/config_util.go` | `logger.*` keys populated from the environment at startup |
| `.env.example` | the six logging keys documented; `LOG_FOLDER` kept as an alias |
| `util/log_rolling_test.go` | new tests: template, both rotation policies, restart append, retention, encoder choice, settings precedence |

## Configuration

| Key | Default | Meaning |
| --- | --- | --- |
| `LOG_DIR` | `./logs` | directory for log files; `LOG_FOLDER` still resolves it when `LOG_DIR` is empty |
| `LOG_FILE_PATTERN` | `cashlenx_{date}{shard}.log` | `{date}` `YYYYMMDD`, `{time}` `HHMMSS`, `{datetime}` `YYYYMMDD-HHMMSS`, `{pid}`, `{shard}` → `_1`, `_2` … |
| `LOG_ROTATION` | `daily` | `daily`, `hourly` or `size` |
| `LOG_MAX_SIZE_MB` | `0` | when positive, also splits a daily or hourly file at that size |
| `LOG_RETENTION_DAYS` | `0` | deletes rolled files of the same template older than this; `0` keeps them |
| `LOG_CONSOLE_FORMAT` | `json` | stdout encoding for collectors; `text` keeps the development format |
| `LOG_LEVEL` | `info` | unchanged |

## Compatibility

- The default template reproduces the previous file name exactly
  (`cashlenx_20261122.log`).
- An existing file is opened for append, never truncated, and its size seeds the
  shard accounting across a restart.
- A template without `{shard}` still gets a numeric suffix, so size rolling can
  never append to the file it just closed.
- `LOG_FOLDER` remains a working alias; a value ending in `.log` is trimmed to
  its directory instead of creating a file with that name.
- The file keeps the production JSON encoder. Only the stdout default moves from
  text to JSON.

## Known limitations

- Size rotation is expressed in whole megabytes; retention sweeps on a period
  change, not on a timer.
- `cashlenx-server/AGENTS.md` still lists the old configuration keys in its
  guide. The edit is approval-gated for agent-instruction files and was not
  applied here.
- No `version/X.Y.Z` tag. The change is on `develop` only: nothing is promoted,
  published or deployed, and no deployment state is claimed.
- The platform ingest contract — credential, label set, retention, hostname — is
  still pending on the `linden` side; the emission side is a prerequisite, not a
  replacement.
