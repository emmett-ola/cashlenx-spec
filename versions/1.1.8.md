## Why

`spec/AGENTS.md` carried `aside: df7ad7a3485c232a229aab88d12715bdb26c3787`
(2026-11-20). The framework moved twice after that stamp, and `check-aside.py`
reported `BEHIND — 2 framework commit(s) since the stamp`:

| Commit | Date | Subject |
| --- | --- | --- |
| `4a9595e08e224d5d8f4d241a411afc4c56631021` | 2026-11-22 | docs: record ESP's measured conformance for the standard's update |
| `9149f70eae768e40a98a972632534f23c6cffc2b` | 2026-11-22 | docs: correct the standard from the 2026-11-22 measurement |

Read before stamping, the two commits changed:

- **§6.1** — ESP is no longer described as having an open difference in its root
  `AGENTS.md`; that file has been a pointer since ESP `0.8.0`.
- **§7** — the migration table is re-measured on 2026-11-22 for all four
  projects and now records each project's stamp state. The CLX row reads
  `23/23` spec standard and `7/7, 6/7, 7/7` engineering baseline, with the
  shared `010` migration prefix as the only remaining item.
- **§7 notes** — being behind the framework is a backlog item with a closing
  version, never a number copied from elsewhere; and a stamp is alignment, not
  acceptance.

Nothing in the changed text adds a requirement CLX does not already meet. The
table's CLX numbers are the ones re-measured below, so the alignment is true and
the stamp belongs in the commit that makes it true.

Stamping `9149f70eae768e40a98a972632534f23c6cffc2b` left one stale sentence
behind it: §7 still said CLX "points at an earlier revision, so CLX reads as
behind until it bumps". ASIDE corrected that in
`ba2338387b59f063533d98b91e1a0716bbe482ca`, which changes no requirement and
only names the revision. Because a framework commit puts every project one
behind, the stamp is carried to that commit here, in the same version, rather
than left describing this repository as behind the revision it just adopted.

`../facts/operations.md` §Migration identity: MongoDB and MySQL keep
independent migration sequences and a shared numeric prefix is not a collision,
so renaming it would change checksum identity. `check-baseline.py` reads one
sequence and reports it; the requirement is not unmet and nothing was renamed.
