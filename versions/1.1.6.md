# 1.1.6 — Restore a green Website build

## Status

- Version: `1.1.6`
- Type: dependency security patch — `vite` `8.3.1` → `8.3.8` inside the existing
  `^8.3.x` range; no source change, no behaviour change.
- State: delivered and promoted on the owner's instruction to keep every
  repository at `main` (see below).
- Date: 2026-11-20.
- Scope: `cashlenx-website` only.

## Why

Promoting `1.1.5` made the Website CI red on `develop`, `testing` and `main`:

```
vite@8.3.1 … high: launch-editor: fs.existsSync() existence check can be
bypassed on Windows (>=8.3.0 <=8.3.2) — GHSA-587h-7wmj-h5pm
1 vulnerability (1 high)
```

`scripts/audit-dependencies.sh` fails the build on any advisory, so the gate
fails closed. The advisory was published after the last green Website run on
2026-10-19; `1.1.5` changed only `scripts/test.sh` and `test/`, and the lockfile
was untouched, so the failure is the dependency set, not the test entry point.
