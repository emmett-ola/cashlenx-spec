## What changed

defines for a multi-repository project: facts in `facts/`, one version ladder,
one record per version, a backlog, and no second home for any of those facts.

## Decisions

1. **The ladder is the version identity; the CLV Idea is the query aid.** This
   supersedes decision `0005` (CLV authoritative version catalog) and the
   matching rules in `0002`/`0004`, because ASIDE §4 keeps version identity in
   the repository where a checkout can resolve it. Implemented in
   `facts/collaboration.md` §Version Model. The Jira side is not yet
   reconciled — see Known limitations.
2. **A structure-only change is a version, and its own version number here,**
   because no product version was open and the change is the deliverable. It is
   labelled `specification only` and leaves every component version untouched.
3. **Pre-standard rows are history, not defects.** The converted records keep
   their original scope, states and evidence; the conversion did not re-verify
   them, and the ladder says so.
4. **No commit column value was invented.** Where a record did not resolve an
   identity commit, the row carries `—` and no tag; a guessed SHA would be a
   false record.
5. **Release evidence is retained, not summarized away.** The six `1.1.3`
   manifests and their checksums moved under `versions/evidence/1.1.3/` and are
   referenced from `1.1.3.md`; deleting proof to satisfy a shape would have been
   the wrong trade.

## Known limitations

- **Jira is not reconciled.** No CLV Idea was created or archived for `1.1.4`,
  and the CLV Ideas still describe themselves as the version authority. The
  repair direction is implementation → repository → Atlassian, so the ladder and
  facts were corrected first; the outstanding Jira edits are
  `backlog/atlassian-version-authority.md`.
- **No tag exists** for any version, including this one. Creating tags is a
  separate controlled action and is not implied by this record.
- **Pre-standard rows are unverified.** Their commits were not resolved from the
  converted records, so no commit or tag was filled in; resolving them is
  deferred rather than guessed.
- **`sources/` still holds imported snapshots** of sibling-project documents.
  They are declared historical input, not current truth; pruning them is
  deferred work, not part of this conversion.
- **`spec/AGENTS.md` content is pending owner approval.** Its rules were moved
  from the retired files, but writing the agent-instruction file needs explicit
  owner consent; until then the file still describes the retired layout.
